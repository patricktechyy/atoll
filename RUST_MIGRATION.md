# Rust migration

Version 0.12.0 introduced a Rust/Tauri host for **Windows and macOS**. It keeps the existing HTML/CSS/JavaScript interface; it is not a rewrite of the UI in Rust. Windows uses WebView2 and macOS uses WKWebView. Electron and Node.js are build/test dependencies only, absent from the Rust application bundle.

The migration is a release candidate, **not a claim of verified full parity**. See `STATE.md` for actual checks. Keep the Electron fallback until both OS builds, real account sessions, privacy permissions and installer/update transitions pass. No platform has been excluded from the migration.

## Build and run

Install Node.js 22, Rust 1.87 or later, and the native platform prerequisites: Xcode Command Line Tools on macOS; Visual Studio C++ Build Tools, Windows SDK and WebView2 on Windows. The lockfile resolves dependencies compatible with Rust 1.87. The Windows installer bootstraps WebView2 when needed.

```sh
npm ci --prefix app
npm start --prefix app                 # quit the other Atoll first; prepare + cargo run
npm run check:rust --prefix app
npm test                              # shared unit and 95-method bridge contract tests
npm run test:rust --prefix app         # Rust unit/storage/network tests
npm run build:rust --prefix app        # optimized .app / NSIS installer for current OS
```

The outputs are `rust/target/release/bundle/macos/Atoll.app` and `rust/target/release/bundle/nsis/*.exe`. Rust builds never replace `/Applications/Atoll.app` automatically. For a certificate-signed Mac build, set `ATOLL_SIGN_IDENTITY` to the same certificate used previously. Otherwise Tauri signs ad hoc, with the existing permission-reset caveat.

Run real OS WebView tests in a logged-in desktop session:

```sh
# macOS
ATOLL_RUST_APP="$PWD/rust/target/release/bundle/macos/Atoll.app" npm run test:rust:ui --prefix app
# PowerShell on Windows
$env:ATOLL_RUST_APP="$PWD\rust\target\release\Atoll.exe"
npm run test:rust:ui --prefix app
```

The harness launches a disposable profile, disables account/permission changes, uses a loopback update feed, and never executes an installer. A failed test retains its temporary profile for inspection. It exercises both layouts, camera clearance, settings, setup, notifications, persistence, native metrics/battery, shortcuts, lyric policy, parser/translation helpers and updater failure/recovery. A method-count test alone does not prove native behavior.

The Electron implementation remains available through `npm run start:electron --prefix app`, `npm run build:mac:electron --prefix app` and `npm run dist:win:electron:dir --prefix app`. Existing Playwright `test:ui`, `test:mac`, and `test:win` commands target that implementation. CI runs these regression checks alongside a separate Rust matrix; do not point an Electron Playwright launcher at a Rust executable.

## Feature implementation

| Behavior | Rust implementation on both OSes |
| --- | --- |
| Layouts, themes, integrated camera notch, lyrics display/translation, tasks, focus/water, reminders and shelf | Existing shared renderer and shared pure parsing/matching functions generated by `tools/prepare-rust.js` |
| Desktop API | `rust/src/rpc.rs` and `app/renderer/rust-bridge.js`; preserves all 95 public renderer methods |
| Media, volume, keyboard/device indicators, clipboard signals, screen capture | Existing native macOS/Windows companions; Rust owns their IPC/restarts. Windows retains core + PowerShell and full PowerShell fallbacks |
| Physical camera/monitor geometry and Mac permissions/calendar | Objective-C C ABI in `native/mac/rust-platform.m`, with no N-API dependency |
| Clipboard, file icons and native drag | Rust clipboard/image storage, native file icons, Tauri drag/drop |
| Battery/charging HUD | IOKit on macOS, GetSystemPowerStatus on Windows; BatteryManager-compatible events in the bridge |
| Networking, player sessions, Todolist, calendar ICS | Rust HTTP client; existing JS calendar/lyrics/translation/task algorithms retained |
| Tray, shortcuts, click-through, monitor switching, autostart | Native Tauri APIs and Rust polling, behind platform capabilities |
| In-app updates | Existing feed filenames/checksums; Rust download/validation. Mac app swapper; Windows NSIS, Restart and install on quit |

The intentional differences in `PARITY.md`, including macOS-only EventKit and different media integrations, remain applicable.

## Data and account migration

The app identifier remains `app.atoll.notch`; the data path stays `~/Library/Application Support/Atoll` or `%APPDATA%\Atoll`. Before merging defaults into existing settings, Rust saves `atoll.pre-rust.json` once. Unknown keys, tasks, shelf paths, clipboard files/history, focus/water data and positions are retained. A saved Windows monitor choice may need re-selection because the hosts use different monitor identifiers. Invalid existing JSON is refused without overwriting it. Writes are serialized and replaced atomically on both platforms.

The Windows NSIS hook also backs up the profile before removing the legacy Electron installation. It handles the old updater's `--force-run` argument and the new updater's `/R` relaunch flag. Actual Electron → Rust installation and Rust → Rust updates still require real Windows verification.

**Reconnect Spotify, Apple Music and Todolist once.** OS WebViews cannot reuse Electron's encrypted browser sessions. New tokens/cookies use Keychain on macOS or Windows Credential Manager, rather than the public settings bridge. Remote player windows can invoke only their own token-capture command; desktop commands require a bundled local window and origin. Sign-in, silent refresh, popups and disconnect must also be verified using real accounts on each OS.

## Verification still required

- Real Windows compile, packaged WebView2 tests, notifications, helper fallbacks, file icons, clipboard/paste, screenshots, mixed-DPI monitors and autostart. Cross-compiling from this Mac stopped at the missing Windows SDK; that is not Windows verification.
- The installed Mac 0.12.1 app now successfully displays the reported “HAHAHA” lyrics through the real Apple Music account. Still verify Windows Apple Music and both-platform Spotify, other player/control scenarios, account refresh/popups/disconnect and Todolist CRUD.
- Actual Mac privacy prompts and persistence of grants, EventKit event selection and screen capture on a permission-granted build; native dragging and Spaces/fullscreen transitions.
- End-to-end installer migration and consecutive-version update/relaunch on each OS. The automated Rust updater fixture tests failure/recovery without installing.
- The Electron software-rendering switch has a WebView2 implementation on Windows. The [public WKPreferences API](https://developer.apple.com/documentation/webkit/wkpreferences) exposes no equivalent GPU-off switch: the Rust Mac UI must explain system-managed graphics rather than pretend the preference is applied. This remains a migration behavior difference to review; the Electron fallback retains the old control.
- Measure total app memory/CPU at matched idle and active workloads. The Rust diagnostics deliberately label **host + companion only**, excluding OS-managed WebView processes, so these numbers must not be presented as total-app savings.

## Packaging and releases

`node tools/rust-release.js` packages release outputs in `dist/rust` with the existing asset names and feeds: `Atoll-macOS-arm64.zip`, `latest-mac.json`, `Atoll-Setup-<version>.exe`, `latest.yml`, plus the legacy blockmap. The feeds remain readable by existing updaters; Windows versions through 0.11.5 still need a manual Setup installation because their updater is broken.

Both CI and Release build/test Rust on macOS and Windows. No release has been published by this migration. Do not announce full parity before the remaining platform checks pass.
